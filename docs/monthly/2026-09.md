## Executive Summary

2026年9月は、**AIによるサイバー攻撃能力の高度化、Identity Trustの悪用、規制対応の実運用化、Cyber Dependencyの拡大**が同時に進み、個別Controlだけでは企業リスクを閉じられないことが明確になった月です。

AI Securityでは、モデル提供者によるCritical Cyber Capabilityの評価と、Unit 42によるAI-assisted Intrusionの実侵害報告が公表されました。両者は**能力評価と実環境観測という異なるEvidence**であり、混同すべきではありません。一方、企業側にとってはAI Toolの権限・隔離・監視と、Identity・Cloud・CI/CDを横断した迅速なContainmentが共通課題となります。

Identity Securityでは、Teams上のIT Support偽装、Passkey/MFA更新を口実としたSocial Engineering、TokenやSessionの悪用が主要論点となりました。Passkey自体の暗号方式だけでなく、**Enrollment、Recovery、Device Code、追加認証手段、Session Token**を別の高リスク操作として守る必要があります。NIST IR 8587はTokenとAssertionの保護をIdentity基盤の設計課題として整理しました。

RegulationではEU Cyber Resilience Actの報告義務が9月11日に適用開始され、製品セキュリティ、PSIRT/CSIRT、法務、事業責任者の連携が不可欠となりました。報告義務の対象となる製品・事象かどうかは個別に判定する必要があります。

ENISA Threat Landscape 2026は、2025年のEUで観測された事象を基に、Supply ChainやThird-partyを含む**Cyber Dependencyが攻撃面と事業影響を拡大する構造**を指摘しました。これは日本企業の被害発生率を直接示すものではありませんが、依存関係とResilienceを管理するうえで参考になります。

**9月の経営上の結論は、Identity、AI、Cloud、Supplier、Incident Responseを横断した統制と証跡管理へ移行することです。**

</div>

## 9月の8つの構造変化

| 構造変化 | 経営上の意味 |
| --- | --- |
| Frontier Cyber AIがCritical Thresholdへ | Capability Levelに応じたAccess / Isolation / Monitoringが必要 |
| AI-assisted Intrusionが時間を圧縮 | 日単位Responseから複数Control Planeの同期Containmentへ |
| Collaboration / Helpdesk Trustが侵入口へ | MFAだけでなくSupport Identity / Remote Sessionを統制する |
| Passkey周辺のEnrollment / Token Flowが攻撃面へ | Phishing-resistant MFAでも登録・回復・Sessionを別途保護する |
| Token / Assertion ProtectionがIdentity基盤要件へ | Signing Key、Verification、Revocation、Short-lived Tokenを設計する |
| CRA報告が24h / 72hの実運用へ | Product SecurityとLegal / PSIRT / CSIRTのReporting Clockを接続する |
| AI SafeguardがEvidence Architectureへ | ZDR、Custody、Attestation、Provenance、Mediationを設計する |
| Cyber DependencyがResilience Riskへ | Supplier / Cloud / Software依存をIncident ImpactとRecoveryの観点で把握する |

## Management View

9月のCore Themesから、経営・CISOが確認すべき論点は次の7点です。

1. **Critical級Cyber Capabilityを持つAI Toolへ、誰がどのCredential / Network / Execution権限でアクセスできるか**
2. **AI-assisted Intrusionを含む高速侵入に対して、Identity / CI/CD / Cloud / AIの権限を連動して封じ込められるか**
3. **Teams / Voice / Helpdesk / RMMの正規Supportを利用者が検証できるか**
4. **Passkey / MFAのEnrollment、Recovery、Device Code、追加認証手段を高リスク操作として統制しているか**
5. **Token Signing Key、Verification、Revocation、Session Invalidation、Workload Identityを一貫して管理しているか**
6. **EU向け製品のCRA報告対象判定と、24h / 72h Reporting ClockのOwner・Evidenceを明確にしているか**
7. **Cloud / SaaS / Supplier / Software / AIへの依存が重要Business Serviceへどう波及するか把握しているか**
