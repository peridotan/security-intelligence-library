## Executive Summary

9月は、**AI Capabilityの上昇、Identity Trustの悪用、Security Regulationの運用開始、Cyber Dependencyの拡大**が同時に進んだ月です。

月初には、GPT-6 AstraがCritical Cybersecurity Capabilityへ到達したというVendor Evaluationと、Frontier AI / Agentic Frameworkを用いて50超のATT&CK Techniqueを10時間未満で横断したUnit 42の実侵害報告が並びました。Evidenceの性質は異なりますが、AI Cyber Riskが「将来のCapability論」から「現在の攻撃・防御運用」へ移りつつあることを示します。

Identity側では、TeamsでIT Supportを装うRemote Session型侵入に続き、MicrosoftがPasskey / MFA / SSO更新を口実にしたSocial EngineeringからCloud Identity侵害へ進むCampaignを報告しました。重要なのはPasskey自体の暗号強度ではなく、**登録・回復・Device Code・Session Token・追加認証手段といった周辺Control Plane**です。NIST IR 8587のFinalも、Token / AssertionのSigning Key、Verification、Lifecycle、Workload Identityを一体で守る必要性を明確にしました。

Regulationでは、9月11日にEU Cyber Resilience Act（CRA）の報告義務が実運用へ入り、Actively Exploited VulnerabilityとSevere Incidentについて24時間のEarly Warning、72時間のFull Notificationが必要になりました。ENISAのSingle Reporting Platformも同日稼働しています。

9月22日に公開されたENISA Threat Landscape 2026は、2025年中の観測データを基に、Ransomware、DDoS、Vulnerability Exploitationに加えて、Supply Chain / Third-partyを含む**Cyber DependencyがDigital Resilienceを弱める構造**を強調しました。これは9月の「単一製品・単一ControlだけではRiskを閉じられない」という流れとも整合します。

> **このページは9月24日時点のCurrent Reviewです。月末のFinal ReviewでCore Themeの入替、優先順位、Evidence表現を再評価します。**

## 9月24日時点の8つの構造変化

| 構造変化 | 経営上の意味 |
| --- | --- |
| Frontier Cyber AIがCritical Thresholdへ | Capability Levelに応じたAccess / Isolation / Monitoringが必要 |
| AI-assisted Intrusionが時間を圧縮 | 日単位Responseから複数Control Planeの同期Containmentへ |
| Collaboration / Helpdesk Trustが侵入口へ | MFAだけでなくSupport Identity / Remote Sessionを統制する |
| Passkey周辺のEnrollment / Token Flowが攻撃面へ | Phishing-resistant MFAでも登録・回復・Sessionを別途保護する |
| Token / Assertion ProtectionがIdentity基盤要件へ | Signing Key、Verification、Revocation、Short-lived Tokenを設計する |
| CRA報告が24h / 72hの実運用へ | Product SecurityとLegal / PSIRT / CSIRTのReporting Clockを接続する |
| AI SafeguardがEvidence Architectureへ | ZDR、Custody、Attestation、Provenance、Mediationを設計する |
| Cyber DependencyがResilience Riskへ | Supplier / Cloud / Software依存をIncident ImpactとRecoveryの観点で把握する |

## Management View

9月24日時点で、経営・CISOが確認したいのは次の7点です。

1. **Critical級Cyber Capabilityへ誰が、どのTool / Network権限でAccessできるか**
2. **10時間未満のAttack Timelineを前提にIdentity / CI/CD / Cloud / AIを同期Containmentできるか**
3. **Teams / Voice / Helpdesk / RMMの「正規Support」をUserが検証できるか**
4. **Passkey / MFAのEnrollment・Recovery・Device Code・追加認証手段をUser Loginとは別のHigh-risk Operationとして統制しているか**
5. **Identity / Access TokenのSigning Key、Verification、Revocation、Session Invalidaton、Workload Tokenを一貫して管理できるか**
6. **EU向けProductでCRAの24h / 72h Reporting Clockを開始するOwnerと判断基準が明確か**
7. **Cloud / SaaS / Supplier / Software Dependencyの障害・侵害が、どのBusiness Serviceへ連鎖するか可視化しているか**

月末のFinal Reviewでは、9月25日以降の一次情報を確認した上で、Core 10 Themesの優先順位とQ3 Reviewへの接続を確定します。
