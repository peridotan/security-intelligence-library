## Executive Summary

2026年10月は、**AIを活用する攻撃工程の進展と、AI開発・運用を支える信頼基盤への侵害**が並行した。Google Threat Intelligence Group（GTIG）はAgentic Offensive Frameworkの実際の侵入活動における利用を報告した。一方、LiteLLM 1.107.0の供給網侵害では、開発元が過去の未失効管理キー、OAuthトークン、CI/CD、悪意あるパッケージ配布に至る経路を事後調査で説明している。前者はベンダーによる観測、後者は開発元の調査とMicrosoftの技術分析であり、すべての攻撃が自律化したことを意味しない。

Identity・Trust Infrastructureでは、eMudhraの中間CA鍵問題が、証明書失効だけでなくRoot Store更新と互換性管理の重要性を示した。Googleの10月20日付発表には11月4日の追記があるため、10月末時点の事実と後日の方針を区別する。DNSSEC Root KSKの切り替えについてICANNは広範な障害の兆候なしと報告したが、個別の検証ResolverのTrust Anchor更新状況は各組織で確認すべきである。

脆弱性対応ではPHP2Shellの実悪用とCISA KEV登録を踏まえ、CVSSだけでなく実悪用・露出・資産重要性・保守継続性による判断が必要となった。NIST IR 8547 Finalと国内SCS評価制度の実施ガイド公表は、暗号移行とセキュリティ保証を具体的な棚卸し・検証・証跡へ落とし込む契機となる。

**10月の経営上の結論は、AI・ソフトウェア供給網・Identity・暗号基盤を別々に扱わず、依存関係、資格情報、復旧手順、判断根拠を横断して管理することである。**

## 10月の5つの構造変化

| 構造変化 | 経営上の意味 |
| --- | --- |
| AIが攻撃工程に組み込まれる | Agentの実行権限、監視、封じ込め時間を見直す |
| Software Supply Chainが資格情報と接続 | CI/CD、OAuth、Secrets、依存パッケージを一体で守る |
| Trust Infrastructureが事業継続リスクへ | CA、Root Store、DNSSEC、証明書互換性を管理する |
| 実悪用・Exposureを基準とする脆弱性対応 | KEV、資産重要性、隔離・停止判断を連動する |
| 標準・制度が検証可能なEvidenceへ | PQC、SCS、統制Owner、適用範囲、評価証跡を定義する |

## Management View

経営層・CISOが確認すべき優先事項は次の6点である。

1. **AI Agent・開発環境に与えたCredential、OAuth、CI/CD、Tool権限を把握し、一括停止・失効できるか。**
2. **Supply Chain侵害時、信頼できる環境から再構築し、関連するSecretsとSessionを失効できるか。**
3. **CA・Root Store・DNSSEC・PQCの変更が重要サービスに及ぼす影響と代替策を把握しているか。**
4. **KEV・実悪用・資産重要性・露出に基づいてパッチ、隔離、停止を決定できるか。**
5. **国内の公開API・委託先・クラウド依存を事業継続の観点から追跡できるか。**
6. **SCS評価とPQC移行の対象範囲、Owner、検証結果、例外、Evidenceを管理できるか。**

## Evidence Basis / 解釈上の注意

- Google GTIG・Microsoft等の侵害報告は各組織の観測・技術分析に基づく。日本全体の発生率を示さない。
- LiteLLMの事後調査は10月23日付の開発元の確定版を優先し、初期の推測と区別する。
- eMudhraに関するGoogle記事の11月4日追記は10月末時点の事実として扱わない。
- NISTのPQC指針、IPAのSCSガイド、実際の法的義務の適用範囲は別々に判断する。
- 10 Core Themesは10件の独立した侵害事象を意味しない。国内全事案の網羅性は保証しない。
